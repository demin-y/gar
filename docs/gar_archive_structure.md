# Структура архива ГАР

Оглавление реальной выгрузки `gar_xml_v20260116.zip` (версия 2026.01.16), снятое скриптом
[`examples/tools/gar_toc.py`](../examples/tools/gar_toc.py) без распаковки. Скрипт читает и
локальный файл, и URL (по HTTP Range: только оглавление и несколько КБ из файлов):

```bash
python3 examples/tools/gar_toc.py downloads/full_base/gar_xml_v20260116.zip 43 11
python3 examples/tools/gar_toc.py '<GarXMLDeltaURL>' 43 11 --insecure   # дельта-архив
python3 examples/tools/gar_delta_probe.py --insecure   # последние дельты из API: оглавление и примеры записей
```

Дельта — архив той же структуры с изменёнными записями, см. [Дельта](#дельта) в конце.

## Итог

```
gar_xml_v20260116.zip   ZIP64, 1739 файлов, 49,25 ГБ сжато / 371,17 ГБ несжато
├── version.txt                         "2026.01.16\nv.223"
├── 10 справочников в корне (0,5–90 КБ)
└── 96 папок субъектов: 01–95 и 99, вложенных папок нет
    └── ровно 18 файлов в каждой, по одному на таблицу
```

- Имена файлов: `<ТАБЛИЦА>_<YYYYMMDD>_<guid>.XML`. Дата в имени (`20260115`/`20260116`)
  **не равна** версии выгрузки — версию берём из `version.txt`.
- Папки 80, 81, 82, 84, 85, 88 (бывшие субъекты) содержат все 18 файлов, но почти пустые.
- Каждый XML — одна строка без переводов, начинается с BOM. Пустые атрибуты опускаются
  (у домов без корпуса нет `ADDNUM1`, у иерархии часто нет `AREACODE`).
- В `AS_ADDR_OBJ` лежат и исторические записи (`ISACTUAL="0" ISACTIVE="0"`); у одного
  `OBJECTID` в разных записях может быть разный `LEVEL`.
- `REGIONCODE` в иерархии субъекта 43 — `"43"`.
- Действующий параметр: `CHANGEIDEND="0"`, `ENDDATE="2079-06-06"`.

## Выводы для гема

- Субъект = папка `NN/`; выбор субъектов — записи zip с префиксом `43/`, `11/` плюс корень.
- Один файл на таблицу в субъекте: работ на таблицу ~96 на всю страну, 2 на два субъекта.
- Размеры различаются на порядки (до 4,8 ГБ на файл) — очередь «таблица × субъект»,
  крупные первыми, прогресс по байтам.
- Код субъекта импорт берёт из имени папки.
- Пустые файлы и папки — норма.
- `AS_HOUSES_PARAMS` — самая большая таблица архива (89,6 ГБ): фильтр типов при разборе,
  `house_params` отключаемы.
- Иерархии содержат строки всех объектов, включая квартиры и участки.

## Дельта

Снята у пользователя скриптом `gar_delta_probe.py` 2026-10-02: дельта 2026.09.29
(`https://fias-file.nalog.ru/downloads/2026.09.29/gar_delta_xml.zip`), субъекты 43 и 11.

```
gar_delta_xml.zip   1739 файлов, 19,69 МБ сжато / 186,12 МБ несжато (2026.10.02 — 42 МБ сжато)
├── version.txt                         "2026.09.29\nv.296"
├── те же 10 справочников в корне (полные, 0,5–87 КБ)
└── 96 папок субъектов, ровно 18 файлов в каждой — и пустые (ADDR_OBJ субъекта 11: 0 записей)
```

- Структура, имена файлов (`AS_<ТАБЛИЦА>_20260928_<guid>.XML`, дата в имени на день раньше
  версии) и атрибуты записей — как в полном архиве. Записи полные, не разностные.
- Изменение объекта — две записи с одним `OBJECTID`: старая (прежний `ID`, `ISACTUAL="0"`,
  `ENDDATE` = дата изменения, `NEXTID` = новый `ID`) и новая (новый `ID`, `PREVID` = старый,
  `ENDDATE="2079-06-06"`). Пример: дом `HOUSENUM="36в"` → `"36В"`. Новый объект —
  одна запись `OPERTYPEID="10"`, `PREVID="0"`.
- Ликвидация дома: новая запись `ISACTUAL="1" ISACTIVE="0"` (`OPERTYPEID` 30, 55).
- Иерархии: смена родителя — старая строка `ISACTIVE="0"` с `ENDDATE`, новая строка с новым
  `ID`, `PARENTOBJID` и `PATH`. Строк потомков с новым `PATH` в дельте не было (у 11 перенесённых
  объектов субъекта 43 — 0), поэтому `Gar::Delta` переписывает начало `PATH` потомков сам.
  Бывают и новые строки сразу с `ISACTIVE="0"` (`ENDDATE="2079-06-06"`).
- Параметры: закрытый — прежний `ID`, `CHANGEIDEND` ≠ 0, `ENDDATE` = дата изменения; новый —
  новый `ID`, `CHANGEIDEND="0"`. Массовые изменения бывают: в субъекте 11 — 2 754 записи
  почтового индекса (`TYPEID="5"`) за одну дельту.
- Объёмы субъекта 43 за дельту: `ADDR_OBJ` 4 записи, `HOUSES` 70, `ADM_HIERARCHY` и
  `MUN_HIERARCHY` по 244, `ADDR_OBJ_PARAMS` 34, `HOUSES_PARAMS` 657.
- Выгрузки — по вторникам и пятницам. API `fias.nalog.ru/WebServices` у пользователя не
  ответил (таймаут), файловый сервер `fias-file.nalog.ru` отвечал: адрес API настраивается
  (`config.api_all_versions_url`).
